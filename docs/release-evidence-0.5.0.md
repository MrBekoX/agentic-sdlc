# Release evidence — 0.5.0

Status: release preparation for version 0.5.0. The publish verdict is **do-not-publish**. No tag, GitHub release, marketplace submission, portal upload or repository visibility change was made. On 2026-10-12 the maintainer decided that this repository will not be made public; a later publication goes through a new public repository built from clean source, and that repository needs its own release check.

## Scope and what changed since 0.4.3

The supported release runtimes stay Claude Code and Codex. Kimi Code, Grok CLI and ZCode ship as experimental adapters; they are not 0.5.0 release targets and carry no go/no-go verdict. The changes since 0.4.3 are listed under 0.5.0 in the [changelog](../CHANGELOG.md): runtime resolution of the plugin root, hook hardening, the three experimental adapters, the native lifecycle checker and the marketplace preparation script.

No model run was made for 0.5.0: on 2026-10-12 the maintainer decided not to run new live evaluations for this version. The native lifecycle checks in the [compatibility matrix](publication/compatibility-matrix.md) ran no model turn and do not replace those evaluations. Each row below holds one of three kinds of evidence:

- **Measured on the release commit**: static gates, archive build, verify and reproducibility, version checks and native manifest validation, all without a model call.
- **Carried from byte-identical inputs**: a result measured on an earlier commit whose measured inputs are byte-identical in 0.5.0. Only `codex_routing_eval` is carried; its identity cell records a digest of those inputs, and `tests/test_release_ledger_docs.py` recomputes it.
- **Not measured on 0.5.0**: the row states not-run, or BLOCKED when a named blocker exists, and its evidence cell keeps the earlier history, including the last Codex procedure FAIL. A run that did not happen is recorded neither as a pass nor as a failure.

## Identity definitions

- **BR20 runtime payload identity**: the SHA-256 of the sha256sum-manifest form of the release archive members, one `<member sha256>  <path>` line per member sorted by UTF-8 path, excluding `docs/release-evidence-0.5.0.md` and `docs/release-readiness.md` (`scripts/build_release.py` `payload_identity` with `RUNTIME_PAYLOAD_EXCLUDE`). A later commit that changes only those two files keeps the same identity. Identities in the [0.4.3 ledger](release-evidence-0.4.3.md) excluded `docs/release-evidence-0.4.3.md` and `docs/release-readiness.md`, so they are not comparable with identities recorded here.
- **Skills-only payload identity**: the same manifest form over every member of the BR24 skills-only archive, with no exclusion.
- **Archive hash**: the SHA-256 of the archive file bytes.
- **Routing input digest**: the SHA-256 of the prompt that `scripts/run_routing_eval.py` `build_codex_prompt` builds with an empty user prompt from `load_skills(skills/)`, followed by a newline and the scenario set `tests/skills/routing/using-agentic-sdlc.json` read as text (`codex_routing_input_digest` in `tests/test_release_ledger_docs.py`). It covers everything the Codex description classifier reads except its argv.

## Limits retained in the release decision

- No live model behaviour of 0.5.0 is recorded. Claude routing and both pipeline procedures have no 0.5.0 run; the last Codex procedure measurement failed and no repair of it has been measured. The Codex routing pass is a description-classifier result carried from byte-identical inputs.
- Real-profile Codex hook trust was not touched for 0.5.0; the trust rows describe the 0.4.3 measurement only.
- The native lifecycle evidence ran no model turn. It proves neither hook delivery inside a live session nor skill behaviour.
- Guard coverage is bounded, some checks are advisory or opt-in, and missing or unrecognized transcript evidence can fail open. See the [runtime adapter limits](runtime-adapter.md#limits-of-branch-review-result-and-strict-evidence).
- This repository's history and PR text hold findings that keep it private (rows `history_private_path_finding` and `pr_text_actions_review`).
