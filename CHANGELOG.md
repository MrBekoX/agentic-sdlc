- Command guards:
  - `scan-commit.mjs` scans what the same command stages: `git add … && git commit`, `stage`, commit pathspecs, `-i`, `-o`, `--pathspec-from-file` and `-a` inside a `bash -c` or `eval` payload. It reads the untracked files an `add` stages (ignored ones only under `-f`) and the patch of a top-level `git apply` (CG-1). `rm`, `mv` and `restore --staged` stage no working-tree content, so their paths are not read. Reads are merged per directory (more than 1000 paths, or more than 8 groups, read the whole tree once). The staged diffs of the repositories the line commits in are read first and their findings reported at once; a staging directory that does not exist is skipped, a commit `-C` target that does not exist gets a "NOT scanned" notice, and a `-C` path holding an expansion falls back to the hook's own repository with a notice. The hook spends at most 48 git processes, 14 seconds, 32 MiB of scanned text and 5000 untracked files: a budget cut, a deadline or a signal that kills git during a commit repository's staged read (its diff or its `--name-only` list) denies the commit ("could not scan the staged changes"), and any other cut prints a loud "NOT scanned" notice instead of the hook being killed without a decision. A file named by `-F` or `git apply` is read only when it is a regular file, and at most its first 5 MiB.
  - `destructive-command-guard.mjs` reads unique long-option prefixes (`rm --rec`, `git reset --ha`, `git clean --fo`), `clean.requireForce=false` (inline, `GIT_CONFIG_*`, `--config-env` or stored) and git aliases, `!` aliases included (CG-2). A `clean.requireForce` it cannot read, or one read from a config the call does not use, counts as off, so `git clean -d`, `-x` or `-X` without `-f` is denied unless it is a dry run. Checks that start no process run first; config reads are capped at 4 and 2.5 seconds, and a command over 20000 characters gets the coarse widened scan instead of alias resolution.
  - It also reads an escaped `\>`, `env -S`, brace expansion, `bash -c --`, `eval --`, `exec -a`, here-strings, `su -c`, `find -ok`, `doas` and `busybox` (CG-3), and PowerShell's `iex`/`Invoke-Expression`, dot-sourcing, `-Command` prefixes, `-EncodedCommand` and backtick escapes (CG-9). The wrapper walk runs to a fixed point; more than 64 `env -S` splits leave the command unresolved for the widened scan.
  - Heredoc bodies: every body line is read as a command, as in `f430715`. Two designs that set bodies aside as data each had a High bypass, because the guard's lexer cannot model bash exactly. Only a whole command of one exact shape keeps its body out, and never for the PowerShell tool: `cat > PATH <<'D'`, `cat >> PATH <<'D'`, `cat <<'D' > PATH` (or `>>`), `tee PATH <<'D'`, and `git commit [simple flags] -F - <<'D'`, whose body is still scanned as the commit message. Claude Code's `git commit -m "$(cat <<'D' … D)"` idiom is read line by line, as in `f430715`, because bash ends that heredoc early and runs the next line. `D` is a quoted identifier, the closing line is exactly `D`, `PATH` is a plain relative path (no `..`, dot component, expansion, glob or drive), and nothing comes before the opener or after the closing line. An exact shape is rejected, and every line read, when an earlier body line starts with the delimiter (bash's back-compat closes a heredoc there inside a command substitution) or the command holds a `\r` or `\0`. The exact shape is judged only on the tool's raw command, never on a `bash -c`/`eval` payload or a `!` alias text, whose decoded text can merge a delimiter line into the line above (CG-10). The git guards read `f430715`'s statement split as well as the lexer's, inside `eval`/`bash -c` payloads and `!` aliases too.
  - The destructive guard also reads the command with its comments blanked (bash `#`; PowerShell `#` and `<#…#>`), and its here-document bodies removed, so a quote inside a comment or a body no longer hides the next line. This closes a bypass already present in `f430715` (`# don't forget` followed by a recursive delete on the next line). A `{…}` word holding `"`, `$` or a backtick is left to the normal segmenter instead of brace expansion, so a quoted `$(…)` inside it is still inspected.
  - The git resolver and the destructive guard share one wrapper table, so `env -u`, `timeout --kill-after` and `xargs -L` no longer hide a commit or push (CG-4). The resolver ignores redirections, so `git push origin 2>&1` is judged like `git push origin` (CG-5), and walks `$()`, backticks, `<()`, function definitions and heredocs fed to a shell (CG-7); its work is bounded at 1 MiB plus 8 times the command length, and exhausting it leaves the command unresolved. `branch-guard.mjs` treats `heads/main` as `refs/heads/main` (CG-6). The shared lexer no longer reads a CR as a blank before `#`, and `)` and `((…))` start a new word.
  - The commit-message scan reads `-F -` and `-F /dev/stdin` from a heredoc or here-string, `-Fmsg.txt`, `--fil=` and `--mess` (CG-8).
  - Git alias lookups are cached and capped at 32 per command and 4 seconds (CG-11). An alias left unresolved (past the cap, read from a config the call does not use, past the work budget, or after an exception in the resolver) is not treated as harmless: `scan-commit.mjs` scans every directory a git call on the line runs in as if `commit -a` ran, and `branch-guard.mjs` denies it under `AGENTIC_BRANCH_GUARD_BLOCK=true` and warns otherwise.

  - New secret labels `anthropic-key`, `gitlab-token`, `npm-token` and `huggingface-token`. The one `jwt` entry finds a JWT after `-`, `--`, `_`, any number of dashed words or a long word (`session-eyJ…`), trying one candidate per base64url run. The `openai-key`, `gitlab-token` and `anthropic-key` bodies stop before another start of the same prefix, so a real key glued after a placeholder run of its kind is reported on its own. A match counts as a degenerate placeholder only when the whole match and its first 64 characters are degenerate, so a key followed by padding is still found, and a labelled mask `***MASKED:<label>***` counts as a placeholder in the guards and in redaction. `scripts/sdlc_runner/mask.py` stays byte-equal (SW-1, SW-2).
  - The `json-credential` and `jwt` patterns, and the boundary re-scans of glued tokens, are linear on long lines, so a guard no longer times out and fails open on one (SW-3).

A line is kept byte for byte only when neither its decoded values nor its raw text hold anything to mask, so a secret under an earlier duplicate key is not kept. When the raw scan of a JSONL line masks something, the rewritten line is also redacted as text. Numbers and booleans under a credential key are masked, in raw and `--json` mode, and a numeric password is judged on its source text; on Node 21 or later (`JSON.rawJSON`) a rewritten line keeps every number's source text. A line too deeply nested to decode is redacted as text. A password under a `password` key is masked whole, judged as a placeholder on its original value (so a `$…` or `%…%` passphrase with blanks is masked), and a quoted password value is masked to its closing quote (SW-4).

The worktree scan's per-file fallback stops after 6 seconds and names at most 10 skipped files, counting the rest.
  - The Codex write guard reads `<<"EOF"`, `<<\EOF` and CRLF heredocs (SW-7). On Cursor, deleting a file is no longer write-scanned, and a pre-write event never scans the file on disk (SW-8). `scan-write.mjs` is wired on `NotebookEdit` and reads its `new_source` (SW-9). The advisory worktree scan also runs when another Stop hook set `stop_hook_active` (SW-10).
- Flow, evidence and claim hooks:
  - The Claude flow-order guard also runs on `Bash` and `PowerShell`: a source file written by `sed -i`, a redirect, a heredoc or `tee` counts as an edit, read by the same write-target recognizer the Codex guard uses. The current call is never its own evidence (FH-1). The flow hooks parse a transcript once and analyse at most 128 KiB of each recorded shell command. A longer one is not read, so it is never test-run or write evidence; on Claude it counts as a possible source edit, so inside an active flow Stop keeps every obligation (warn, or block under `AGENTIC_FLOW_GATE_BLOCK=true`), and with no flow it can raise the warn-only completion-claim heuristic. The current command is read up to the recognizer's 512 KiB cap. The shell readers are linear, so no command shape holds a flow hook past its timeout.

A path that names the project through a link (macOS `/var` is `/private/var`) is compared with both sides resolved, so it is gated too, also when a runtime sends no `cwd` and the hook falls back to its own resolved working directory. The retry can only make a path a source file, never hide one. Its work is bounded (128 segments or 4096 characters, 32 folders tried, 64 folders per hook run), so the length of a path cannot make the hook run past its timeout, and past those bounds a path keeps its as-written reading. The Stop guards and the Codex pre-edit guard read every target as written before they resolve any link, so a lookup that stalls (a dead network mount) cannot hide a target that is source as written; the byte-locked Claude pre-edit guard checks its targets one by one, so there a stalled lookup on an earlier target can still run the hook past its timeout. On Windows, UNC and WSL (`\\wsl.localhost\…`) paths are not resolved through links.

A CR ends a heredoc only when it follows the delimiter on the opener line, as bash reads it (FH-5). It no longer counts the edit command's own test run as prior evidence (FH-6).

A claim is hypothetical only through its own clause (if, unless, whether, assuming, provided that or eğer in it, an opening once or until, a modal up to three words before the claim, a Turkish future form) or an earlier clause of its sentence that opens with one of those conditionals and reaches the claim through commas only (a `;` or `:` starts an independent clause), so "Once again, all tests pass" and "If you want a PR, say so; all tests pass." are claims, and a negation counts only inside the claim's sentence (FH-8).

  - `worktree-scan.mjs` opens only regular files. A FIFO, a socket or a device, reached through a link, named by the untracked listing or sitting at the dedup state path, is skipped unread and the other files are still scanned. A FIFO used to block the Stop hook until the runtime killed it, and a killed hook renders no decision.

For the quoted keys and the Bearer token an all-lowercase word of at most three hyphen-joined parts (a type name such as `string`, or prose) is not flagged either; in a URL's userinfo only placeholder words (`password`, `changeme`, `secret`, ...) are. Neither denies for it, each hook writes one JSON object (also next to an unresolved-alias report), and the notice quotes none of the command.
  - Git hooks work on Windows, macOS, Linux and WSL from one install. `install_git_hooks.py` copies the scanner and the three modules it imports into `agentic-sdlc-scanner/` next to the hooks, and each hook finds that folder from its own location (`$0`), so no plugin path is recorded. Before, a checkout installed from Windows (`D:/…`) and committed from WSL (`/mnt/d/…`), or the other way round, ran a hook that could not find the scanner and committed unscanned; a moved repository or plugin did the same.

  - Hardening of the pieces above, from six independent security reviews of this pass:
    - A piped body is scanned in addition to the commit's own stdin, never instead of it: in `cat <<'A' | git commit -F - <<'B'` git reads B, and both are scanned. The body rides on the statement it feeds: on that statement's one reading it adds one invocation record per body, so it adds no queue item, spends no resolver budget and is dropped with its statement. The producer is looked up in the consumer's own region (a `$(…)` inside the consumer does not hide it), and a repeated `git commit -F -` keeps each of its bodies.
    - The skipped-read notice's probe stops at the first hit and shares one character cap per command line; past the cap a dropped statement counts as not inspected without being probed.
    - `scan-commit.mjs` reads each named `-F` message file and `apply` patch file once per resolved path per run, whichever records name it.
    - The Stop scan's dedup state file is never read or written through a link, is used only when it is a regular file with one link that the user owns, and is truncated only after that check; its mode is set on the open descriptor. The default `<tmpdir>/agentic-sdlc` folder is used only when it is a real folder the user owns with no group or other access; otherwise the scan runs without dedup.
    - `install_git_hooks.py` writes each file as a new file, with its mode set, renamed over the target, so a symbolic or hard link planted there is replaced, not written through, and no commit runs an unexecutable hook. A vendored folder that is a symlink or a junction is foreign and never cleaned; a FIFO named like a hook is foreign; a write left behind by an interrupted `--install` (`.<name>.agentic-sdlc-tmp`) is cleaned up; and a legacy body whose scanner path holds `"`, `$`, a backtick or a backslash is not adopted.
    - The hook body never falls back to the current directory when `$0` names no folder, and prints its warnings with `printf`, so a `\c` in the path cannot cut them off.
    - In a URL's userinfo the validator flags a lowercase password too; only placeholder words (`password`, `changeme`, `secret`, ...) stay clean there.
    - `--check` prints the plugin's scanner path as `scanner_source=`; `scanner=` is the vendored copy's state.
